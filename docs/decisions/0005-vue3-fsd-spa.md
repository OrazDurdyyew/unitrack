# 0005. Vue 3 + Vite SPA с архитектурой FSD

Дата: 2026-11-06
Статус: принято

## Контекст

Веб-панель — внутренний инструмент за логином: администрирование, утверждение, сводки. SEO и серверный рендеринг не нужны. API целиком у Go. Главное требование к структуре — жёсткие правила, куда класть код, проверяемые инструментами, а не памятью.

## Решение

Vue 3 с Composition API и `<script setup lang="ts">`, Vite, TypeScript в строгом режиме, pnpm. Архитектура Feature-Sliced Design: слои `app → pages → widgets → features → entities → shared`; слой импортирует только нижележащие; слайсы одного слоя не импортируют друг друга; публичный API слайса — `index.ts`. Правила проверяет ESLint (`eslint-plugin-boundaries`). Сборка — статические файлы, которые раздаёт nginx.

## Последствия

- Плюсы: нет Node в продакшене; структура по смыслу домена, а не по типу файла; нарушение границ — ошибка сборки.
- Минусы и риски: FSD многословна для маленьких фич; не плодить слои ради слоёв (виджет только когда он реально переиспользуется).
- Что сделать: описать слои в `web/CLAUDE.md`; линтер границ в pre-commit и CI.

## Отклонённые варианты

- **Nuxt 4** — его сила (SSR, серверные маршруты) здесь не используется; в режиме SPA остаются только соглашения, а Node-процесс или лишний слой абстракции остаются.
