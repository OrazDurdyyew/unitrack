# 0012. Русский для документов, английский для идентификаторов

Дата: 2026-11-06
Статус: принято

## Контекст

Проект ведут разные сессии Claude и разработчики. ТЗ на русском, пользователи — туркмены, заказчик выбрал русский язык документации 2026-11-06. Инструменты (линтеры, генераторы, фреймворки) и Claude надёжнее работают с английскими идентификаторами.

## Решение

На русском: документация, комментарии в коде, сообщения коммитов (после английского префикса conventional commits), тексты интерфейса (через словарь переводов, базовая локаль `ru`), ADR, STATUS. На английском: имена переменных, функций, типов, таблиц, колонок, файлов и папок, ключи конфигурации и переводов, операции в OpenAPI.

## Последствия

- Плюсы: документы читает заказчик без перевода; код совместим со всеми инструментами.
- Минусы и риски: смешение языков в одном файле — норма, но строки интерфейса в коде запрещены (только через i18n), иначе они окажутся по-русски в коде и не переведутся на туркменский.
- Что сделать: `vue/no-bare-strings-in-template` в ESLint; проверка префикса коммита в хуке.

## Отклонённые варианты

- **Всё на английском** — заказчик и пользователи читают документы по-русски.
- **Туркменский интерфейс сразу** — добавляется позже переводом словаря, без переписывания.
