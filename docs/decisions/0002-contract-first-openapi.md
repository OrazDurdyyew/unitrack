# 0002. Контракт сначала: OpenAPI как источник типов

Дата: 2026-11-06
Статус: принято

## Контекст

Три платформы (Go-сервер, Vue-веб, Kotlin-Android) должны одинаково понимать API. Ручное дублирование типов на трёх языках неизбежно расходится. Нужен один источник истины, из которого всё генерируется.

## Решение

Файл `api/openapi.yaml` (OpenAPI 3.1) пишется руками первым, до кода. Из него генерируются: интерфейсы обработчиков и валидация запросов на сервере (oapi-codegen), TypeScript-клиент для веба (openapi-typescript + openapi-fetch), Kotlin-клиент для Android (openapi-generator). Сервер физически не может принять запрос, не описанный в контракте. Изменение контракта — отдельный коммит с префиксом `api:` и регенерацией всех клиентов в том же изменении; CI проверяет, что сгенерированный код совпадает с контрактом.

## Последствия

- Плюсы: типы никогда не расходятся; контракт читается без кода; Android можно писать параллельно с сервером.
- Минусы и риски: дисциплина «сначала YAML» требует привычки; сгенерированный код в репозитории увеличивает диффы.
- Что сделать: `task gen` регенерирует всё; workflow `contract.yml` падает при расхождении.

## Отклонённые варианты

- **Генерация спеки из кода (code-first)** — спека становится побочным продуктом и отстаёт; Android не может начать, пока сервер не написан.
- **Без спеки, ручные типы** — три копии правды.
