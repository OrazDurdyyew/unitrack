# 0003. sqlc и pgx без ORM, миграции goose

Дата: 2026-11-06
Статус: принято

## Контекст

Система ведёт аудит и работает с 5 000–15 000 студентов. Запросы к базе должны быть видимыми, предсказуемыми по производительности и проверяемыми администратором базы.

## Решение

Драйвер — pgx v5. Запросы пишутся обычным SQL в файлах `*.sql`, sqlc генерирует из них типизированные Go-функции. ORM не используется. Миграции — goose: SQL-файлы с номерами версий, встроены в бинарник, применяются при старте или командой. Применённая миграция не меняется — только новая миграция вперёд. Транзакции открывает сервисный слой.

## Последствия

- Плюсы: весь SQL виден и читаем; нет скрытых запросов и N+1; история схемы в git рядом с кодом.
- Минусы и риски: больше SQL пишется руками; динамические фильтры требуют аккуратности (sqlc поддерживает условные параметры, иначе — явные варианты запроса).
- Что сделать: `sqlc generate` в `task gen`; соглашение о расположении `queries.sql` в каждом модуле.

## Отклонённые варианты

- **GORM** — скрывает SQL, порождает неожиданные запросы, трудно отлаживать.
- **ent** — мощный, но тянет свою модель мира и кодогенерацию с «магией».
- **Голый pgx без sqlc** — ручной маппинг строк в структуры, ошибки находятся в рантайме.
