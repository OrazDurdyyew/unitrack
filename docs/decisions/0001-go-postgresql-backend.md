# 0001. Go и PostgreSQL для сервера

Дата: 2026-11-06
Статус: принято

## Контекст

Сервер работает на собственном железе института без облака (см. 0009). Нужен бэкенд, который ставится одним бинарником, ест мало памяти, стартует за секунду и читается без знания фреймворков — поддерживать его будут разные сессии Claude и разработчики, не обязательно эксперты в выбранном языке. Заказчик при обсуждении 2026-11-06 выбрал Go и PostgreSQL.

## Решение

Сервер пишется на Go (актуальная стабильная версия, сейчас 1.24), база данных — PostgreSQL 17. Принцип набора библиотек: стандартная библиотека прежде сторонних пакетов, минимум зависимостей, никакой «магии». Роутер — chi как тонкая обёртка над `net/http`. Логи — `slog` в JSON. Пароли — argon2id. JWT — golang-jwt. Фоновые задачи — встроенный планировщик в том же процессе.

## Последствия

- Плюсы: один статический бинарник, предсказуемая производительность, явный код, долгоживущая стандартная библиотека.
- Минусы и риски: две среды сборки в репозитории (Go и Node для веба), Android добавит третью (JVM). Заказчик не эксперт в Go — решения по Go объясняются простым языком в ADR и `backend/CLAUDE.md`.
- Что сделать: закрепить версии инструментов через `tool`-директивы в `go.mod`; каждый новый пакет — отдельная запись в ADR.

## Отклонённые варианты

- **Node.js + NestJS** — удобно делить типы с вебом, но тяжелее в продакшене, и типы всё равно делятся через OpenAPI (0002).
- **Kotlin + Spring Boot** — один язык с Android, но JVM тяжелее на железе института, а Spring скрывает слишком много.
- **Python + FastAPI/Django** — быстрый старт, слабее типизация и производительность под 15 000 студентов.
