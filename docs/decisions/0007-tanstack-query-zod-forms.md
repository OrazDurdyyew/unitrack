# 0007. TanStack Query для серверных данных, zod для форм

Дата: 2026-11-06
Статус: принято

## Контекст

В панели 20–30 экранов со списками и мутациями. Каждому нужны состояние загрузки и ошибки, кеш, обновление после действия, защита от двойного запроса. Формы — около 15, с одинаковыми правилами показа ошибок.

## Решение

Серверные данные — только через TanStack Query (`@tanstack/vue-query`) в `entities/*/model`; запросы — в `entities/*/api` через сгенерированный клиент. Pinia — только для клиентского состояния: сессия, настройки интерфейса. Формы — схемы zod плюс собственный composable `useForm` на ~50 строк в `shared/lib/form`; vee-validate не используется. Zod также проверяет ответы сервера там, где это важно, настройки окружения и данные из localStorage.

## Последствия

- Плюсы: нет ручного слежения за свежестью данных в сторах; единый способ показа ошибок форм; один пакет для валидации вместо двух.
- Минусы и риски: ещё одна зависимость (TanStack Query ~13 КБ) — оправдана объёмом убранного кода.
- Что сделать: написать `useForm` на этапе 2 вместе с первой формой.

## Отклонённые варианты

- **Ответы API в Pinia** — классическая ошибка: ручная инвалидация, устаревшие данные.
- **vee-validate + zod** — два пакета там, где хватает одного.
