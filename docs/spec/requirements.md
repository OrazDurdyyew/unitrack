## 1. Обзор

Этот проект представляет собой **цифровую систему управления посещаемостью студентов и учебными процессами** в институте экономики и менеджмента в Туркменистане.

В настоящее время все процессы выполняются вручную:

- Утренние проверки посещаемости (наличие студентов в общежитии или на собрании)
- Вечерние проверки в общежитии
- Отслеживание посещаемости мероприятий (например, субботника)
- Различные внутренние отчеты и списки

Цель этой системы — **оцифровать и оптимизировать эти процессы**, позволяя сотрудникам:

- Регистрировать посещаемость с мобильных устройств
- Мгновенно отправлять отчеты
- Просматривать и утверждать отчеты с помощью иерархического рабочего процесса

Эта система предназначена для:

- Обеспечения безопасности
- Масштабируемости
- Гибкости (в пределах контролируемых ограничений)
- Расширяемости для будущих академических функций

## 2. Ключевые пользователи и роли

### Организационная структура

- Ректор
- Проректора (2)
- Сотрудники ректората (10–15 человек)
- Факультеты
  - Декан
  - Заместители декана (5–7 на факультет)
  - Преподаватели (~500)
  - Студенты (~5000, масштабирование до 10000–15000)

### Примечание о «лидере группы»

- «Лидер группы» **не** является системной ролью с правами доступа
- Это атрибут в записи студента, указывающий на то, что студент является избранным лидером своей группы
- Этот атрибут не предоставляет прав на запись или чтение
- Используется только для информационного отображения (например, отображается рядом с именем студента в списках групп)
- Лидеры групп **не** проходят аутентификацию в системе и не выполняют никаких действий

## 3. Основная проблема

В настоящее время:

- Посещаемость отслеживается вручную
- Данные непоследовательны и обрабатываются медленно
- Нет централизованной системы
- Нет журнала аудита

Нам необходимо:

- Ввод данных в режиме реального времени
- Структурированная отчетность
- Контролируемое редактирование и утверждение
- Полная отслеживаемость

## 4. Основная функция: посещаемость и составление отчётов

### Рабочий процесс

1. Заместитель декана составляет отчет (например, о посещаемости утром)
2. Отмечает студентов:
   - Присутствует
   - Отсутствует
3. Если отсутствует:
   - Выбирает причину из списка контролируемых причин (или «Другое» с обязательным комментарием)
4. Может редактировать данные перед отправкой
5. Отправляет отчет

### Процесс утверждения

- Заместитель декана → отправляет
- Декан → проверяет, при необходимости редактирует, отправляет
- Ректорат → окончательная проверка, при необходимости редактирует

### 4.1. Причины отсутствия

#### Структура

- Предопределенный список причин + один вариант «Другое», требующий обязательного комментария в свободной форме
- Нет пользовательских причин

#### Хранение

Таблица `absence_reasons`:

| Поле | Тип | Назначение |
|---|---|---|
| `id` | идентификатор | первичный ключ |
| `code` | строка | машинный код причины |
| `name` | строка | название для отображения |
| `requires_document` | bool | требуется ли подтверждающий документ |
| `is_active` | bool | активна ли причина (мягкое удаление) |

- Управляется ректоратом через панель администратора
- Мягкое удаление (`is_active = false`) вместо жесткого удаления для сохранения истории

#### Начальные значения по умолчанию

- Болезнь (с медицинской справкой)
- Болезнь (без медицинской справки)
- Семейные обстоятельства
- Академический отпуск
- Академическая поездка / конкурс
- Опоздание
- Другое (требует комментария)

#### Подтверждающие документы

- Флаг `requires_document` управляет пользовательским интерфейсом: если он равен true, в форме отображается флажок «Документ предоставлен»
- В версии 1 загрузка файлов невозможна — только подтверждение флаг
- Вложенные файлы могут быть рассмотрены на более позднем этапе

#### Процесс проверки

- Каждый семестр ректорат проверяет накопленные комментарии категории «Другое» через панель администратора
- Часто повторяющиеся причины добавляются в предопределенный список
- Это ручной операционный процесс, а не автоматизированный рабочий процесс

### 4.2. Процесс запроса на изменение

#### Утверждающий = текущий этап соответствующего отчета

Роль, утверждающая запрос на изменение, определяется **тем, где отчет находится в рабочем процессе**, а не тем, кто запрашивает изменение.

- Отчет все еще находится на стадии вице-декана (черновик) → запрос на изменение не требуется; Вице-декан вносит правки напрямую
- Отчет на этапе декана (отправлен, ожидает рассмотрения деканом) → Декан утверждает запросы на изменения
- Отчет на этапе ректората (отправлен деканом, ожидает окончательного утверждения) → Ректорат утверждает
- Отчет доработан ректоратом → Ректорат утверждает любые дальнейшие запросы на изменения

Таким образом, вице-декан может напрямую отправить запрос на изменение отчета, находящегося в ведении ректората; он поступает непосредственно в ректорат на утверждение (без перехода через декана), но декан факультета все равно его видит.

#### Массовые запросы

- Один запрос на изменение может содержать несколько изменений полей для одного отчета.
- Утверждается или отклоняется как единое целое (без утверждения по строкам).
- Если рецензент не согласен с одним пунктом, он отклоняет весь запрос, и автор отправляет его повторно без проблемного пункта.

#### Отклонение

- В случае отклонения исходные данные отчета остаются неизменными.
- Отклонение регистрируется с обязательным комментарием рецензента.
- Автор может создать новый (исправленный) запрос на изменение.
- Отклоненные запросы видны на вкладке истории отчета.

#### Напоминания (без жесткого крайнего срока)

- Автоматическое отклонение по истечении времени ожидания не предусмотрено.
- Уведомление-напоминание повторно отправляется утверждающему лицу через 3 дня бездействия.
- Второе напоминание через 7 дней.

#### Неизменяемость после утверждения

- После утверждения запрос на изменение нельзя редактировать.
- Для дальнейших изменений требуется новый запрос на изменение.

#### Видимость

- Заместитель декана: видит свои собственные запросы на изменение. (любой статус)
- Декан: просматривает все запросы на изменения, затрагивающие отчеты его преподавателей.
